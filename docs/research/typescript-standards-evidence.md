**A3 notes.** From the 6.0 notes, changes that reach TS 7:

- `strict` now defaults to `true`; `module` defaults to `esnext`; `target` defaults to latest ES (`es2025`); `types` defaults to `[]` ("`types: ["*"]` restores the 5.9 behavior"); `rootDir` defaults to the tsconfig directory.
- `moduleResolution node` (node10) is deprecated, with `nodenext`/`bundler` as replacements; `classic` removed. The notes warn deprecated options "are removed entirely in TypeScript 7.0".
- `esModuleInterop` and `allowSyntheticDefaultImports` can no longer be `false`; `baseUrl` deprecated; `outFile` removed.
- `typescript-go` CHANGES.md lists no option removals; its `strict` notes are about `undefined`-typed parameter omission and JSDoc `@param`.
- NF (not mentioned in any source read): `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`, `isolatedModules`, `erasableSyntaxOnly`, `noEmit`, `jsx: react-jsx`. No removal or default change is documented for them, but "no mention" is not "verified unchanged". NodeNext and Bundler are the recommended resolution modes in the 6.0 notes. Check against the real 7.0 tsconfig reference before asserting.

**B5 notes (breaking changes 40-46, from main's breaking-changes.md; file was only read to char 100000 of 141147, which covers 46 down to 40).**

- 45.0: workers created from subframes need `nodeIntegrationInSubFrames` for Node integration (affects `nodeIntegrationInWorker` reasoning).
- 45.0: screen capture is reported as `display-capture` in permission request handlers, not `media`. Handlers must handle it.
- 45.0: `window.open()` children of unsandboxed windows get their own sandboxed process; `setWindowOpenHandler` can override `sandbox`/`nodeIntegration`.
- 45.0: sandboxed preloads lose Node shims and `Buffer`/`setImmediate` globals.
- 42.0: the `electron` npm package no longer downloads its binary in a `postinstall` script (affects install/CI standards).
- No listed changes to webview, protocol, spellcheck or crashReporter in 40-46. 47.0 (not yet stable) removes the `top-level-storage-access` permission.

**B6 notes (ASAR integrity, v45.3.1 docs).** Quote: fuse "Available on macOS and Windows only". macOS needs `electron>=16`, Windows `electron>=30`; Linux not listed. Limits: labelled experimental; `app.asar` must come from `@electron/asar`; the fuse is off by default; enable `onlyLoadAppFromAsar` too or the check "can be bypassed through the app code search path"; macOS accepts SHA256 only; hash is the ASAR header hash supplied at packaging time (Info.plist `ElectronAsarIntegrity` on macOS, `Integrity`/`ElectronAsar` resource on Windows); missing or mismatched hash terminates the app. Other fuse caveats: `cookieEncryption` is one-way; `nodeCliInspect` off also disables `SIGUSR1` inspector start.

## Corrections to carry into the standards

1. Claim 2 is wrong as of 2026-11-13: typescript-eslint 8.72.2 declares `typescript <6.1.0`.
2. Claim 8a is wrong: an empty language list falls back to `en-US`; use `setSpellCheckerDictionaryDownloadURL` or accept the download.
3. Claim 8b: probe confirmed (Google DNS IPv6, UDP, 443), "cannot be disabled" unproven; Chromium has override features.
4. Claim 10: the default template uses `{-snapshotSuffix}`, not `{platform}`.
5. Claim 11: nonce goes through Griffel `RendererProvider`; `FluentProvider` has no nonce/renderer prop.
6. Claim 12: only SVG text gets inline `style`; CSP effect is inference.
7. ASAR integrity: Windows and macOS only, not Linux.
8. Playwright `_electron.launch` always passes `--inspect=0` and `--remote-debugging-port=0`; no pipe support found.
