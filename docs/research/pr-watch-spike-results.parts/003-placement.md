### Recommended output contract (placement-independent)

Defined so it is identical whichever placement wins in P2, and so G2's state decision does not change it.

- Invocation takes `owner/repo` and a PR number; an optional opaque cursor is accepted and returned only if G2 chooses a cursor model.
- Stdout is one JSON object, UTF-8, no ANSI. Stderr carries diagnostics only. Never prints a token or any environment value.
- Fields: PR identity and head SHA; one `state` from a closed set (for example `clean`, `pending`, `failing`, `needs-attention`, `conflicted`, `merged`, `closed`); per-check name and conclusion for non-green checks; counts and URLs of new feedback items; `author_association` and `user.type` per actor; a `permitted` boolean per actor (rule per S5); fetch timestamp.
- Never includes comment, review or PR-title bodies. The agent fetches a body deliberately, as data (Plan Section 7: the digest must not carry attacker-controlled instructions).
- Exit codes: 0 digest produced (including "needs-attention"); a distinct non-zero code for "cannot reach GitHub or auth failed" so a dead watcher is not mistaken for "no change" (risk "Silent watcher death", `docs/research/desktop-pr-tracking.md:169`).
- Pure functions (classify checks, apply actor rule, build digest) separated from one thin I/O function that calls `ai-git gh-api` (credential stays in `ai-git`, ADR 0005).
- Same contract whether the wake is a subscription event, a backgrounded wait, a Monitor line, or a hook.

### Recommendation

- **Recommended: C, a skill-local script**, `skills/pr-stewardship/scripts/`, Node built-ins only, invoked `node <skill base dir>/scripts/<name>.js`, calling `ai-git gh-api` through `child_process` so credentials stay in `ai-git` (ADR 0005). Rationale: agent-only audience (P1), already ships in the `engineering` bundle for both callers (P3), wake-agnostic, smallest surface, no new component type.
- **Runner-up: D, an MCP server.** It is the ADR 0004 default and the only route to a push wake. Its case is strong **only if** W5/P4 show a channel is viable and G1 adopts it; today those are Unverified, and adopting Channels is a flagged Architect fork.
- Not recommended: **A** (wrong audience and home), **B** (dilutes the credential boundary ADR 0005 protects), **E** alone (not deterministic; keep prose as the wrapper around whichever tool wins).
- Cost the recommendation accepts: no exec bit (call with `node`), no dependencies, tests outside the skill, snapshot churn, cloud presence unproven until W7, Kiro path discovery unproven.
- The pure logic could be written so it moves unchanged into option D later (digest functions in one importable module; the CLI entry is a thin wrapper), which keeps C reversible toward D. This is a design note, not a plan.
