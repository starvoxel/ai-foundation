## Scope

**This steering applies to:** All agents, whenever creating or editing a `.md` file.

**Loaded when:** When working with files matching `**/*.md`.

---

## Rules

### Rule 1: Do Not Manually Hard-Wrap Prose

- When writing a paragraph or bullet item, write it as one continuous logical line in the source (or let the editor soft-wrap it) — do not insert a line break every ~80 characters mid-sentence
- A paragraph or list item is one logical unit of text; only actual paragraph, list-item, or section boundaries get a line break in the rendered output
- This applies to prose content specifically — tables, code blocks, YAML frontmatter, and Markdown's explicit hard-break syntax (a line ending in two trailing spaces, used intentionally) are unaffected and follow their own formatting rules

**Rationale:** Manually hard-wrapped prose produces noisy diffs (a single wording change touches every line in the paragraph), breaks natural reflow in renderers and editors, and reads as if it were generated by inserting literal line breaks rather than authored as flowing text.

**Exceptions:** None for prose paragraphs and bullet items. Tables, code blocks, frontmatter, and intentional Markdown hard breaks are governed by their own formatting conventions, not this rule.

---

## Enforcement

- **Formatting violations:** Caught during self-validation before presenting output, or during human/review inspection. This is a MEDIUM-severity formatting finding (not a correctness issue) — the agent should reflow the affected paragraph(s) before the artifact is considered complete.

---

## Notes

This rule targets manually inserted mid-sentence line breaks, not markdown line length in general. Long single-line paragraphs are correct under this rule; the problem is a line break appearing in the middle of what should be one continuous sentence or bullet.
